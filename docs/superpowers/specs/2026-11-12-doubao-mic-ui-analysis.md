## 1. 豆包这个界面长什么样

拆开看，左边是「听」，右边是「想」，中间一条竖线：

| 位置 | 元素 | 说明 |
|------|------|------|
| 左上 | 大标题「新录音」 | 24pt 粗体，不是控件栏里的一行小字 |
| 左上 | 三个下拉胶囊 | 自动识别 ⌄ / 不翻译 ⌄ / 保留音频 ⌄ —— 每个都带 `⌄`，是**菜单**不是开关 |
| 左中 | 逐句转写 | **按说话人分块**：一块一个彩色圆头像 + 「说话人 1」+ `⌄` 下拉 + `· 00:15` 时间戳，下面跟这段话 |
| 左下 | 整段波形条 | 一条贯穿的波形，密度随语音起伏，能看见整场录音的节奏 |
| 底左 | 计时 `02:26` | |
| 底中 | 大蓝「暂停」键 + 灰色方块「停止」键 | 暂停是一等公民 |
| 文中 | 悬浮圆形下箭头 | 往下滚的浮动按钮 |
| 右上 | 「实时总结」+ 两个图标 | 折叠 / 切视图 |
| 右中 | **思维导图式的议题树** | 竖线主干 + 圆角连线，每个议题一个彩色胶囊（蓝「人物身份确认」、橙「个人状态分享」），下挂一段说明卡片 |
| 右下 | 「当前正在聊…」 | 虚线竖轴上的条目，最新一条实心圆点 |

## 2. 和知了现在的「实时识别」页比

知了现在这张图（opencode 合并后的实拍）已经是：顶部「系统声音 / 麦克风」来源切换 → 一行控件 → 左侧转写 → 右侧实时纪要。**「实时纪要」那一栏保留了**，正是你要的。

差在五个地方：

| # | 豆包 | 知了现在 | 差在哪 |
|---|------|---------|--------|
| 1 | 说话人分块 + 头像 + 改名下拉 | 句首一行「● 人物 1」 | 有了分块的**视觉**，但**没有头像，也没有改名入口**（`SpeakerEditor` 只挂在会议记录窗口 `Views.swift:1098`，识别页上够不着） |
| 2 | 底部大「暂停」 | 只有一个红点「停止」 | `RecordEngine.State` 只有 idle/preparing/recording/stopping —— **没有 paused** |
| 3 | 整段波形条（可拖） | 96×26 的实时电平表（`RecordScope`，只留最近 40 个采样） | 电平表是「现在多响」，豆包那条是「整场长什么样」 |
| 4 | 右侧思维导图议题树 + 悬浮下箭头 | 议题是**平铺的卡片**，没有树 | 议题树让人一眼看出「从哪枝长出来的」 |
| 5 | 每块带 `⌄`，三个都是菜单 | 自动识别 / 保留音频是**开关** | 豆包这三个都能展开挑选，不是开关 |

## 3. 借鉴清单（按性价比排）

### 3.1 一定要借：说话人改名入口 —— 现有零件全齐，只是没接上

`SpeakerEditor`（改名/合并）已经写好了，就挂在会议记录窗口。识别页上补一个入口即可：

- 转写里每块说话人的「人物 1」改成**头像 + 名字 + `⌄`**，点开是 `SpeakerEditor`
- 用现成的 `SpeakerColor.ink(person)` 上色（4 色，`SpeakerID.swift`）
- 豆包的头像是**填充圆**，知了现在是 6pt 小圆点 —— 直接换成 20pt 头像圆，成本几乎为零

这是**最高性价比**的一条：零件全在，缺的是接线。

### 3.2 值得借：暂停

豆包把「暂停」做成底部最大的一颗按钮，因为它录的是长时间会议，中途要停一下是高频动作。

知了 `RecordEngine.State` 加一个 `.paused` 即可：暂停时 analyzer 停止喂音频、计时停住、波形冻结，音频文件继续写。系统声音那侧（`ListenEngine`）也该有。

⚠️ 这一条要动引擎，不是纯 UI，是本清单里唯一有技术风险的一项。

### 3.3 值得借：整段波形条

豆包底部那条波形是**整场录音**，看得见谁说了多久、哪儿有停顿。它同时是天然的进度条。

知了现在是 `RecordScope`：96×26、24 根柱、只留最近 40 个采样（`scopeSamples = 40`）。要做整段的，需要在引擎里攒一份全程电平（或从已存的 m4a 画）。这条**要先有暂停/停止的状态机才好做**，建议排在暂停之后。

### 3.4 可以借：右侧议题树

豆包的右侧是竖线主干 + 圆角分支的思维导图。知了的议题现在是平铺卡片（「了解中国历史的需求」一块，下面带要点和鱼骨图）。

议题树的好处是**能看出议题之间的关系**（哪些是从哪条分出去的）。知了现在有 `NoteTopic`（`title` / `points` / `start` / `fishbone`），数据够画树，缺的是布局。

⚠️ 但**这一条要节制**：知了右侧已经有鱼骨图和结论待办，是「读完能带走」的结构；豆包那种树是「看结构」的。加树不能把鱼骨图挤掉 —— 建议树和鱼骨图**分层**，不互相替代。

### 3.5 可以借：悬浮下箭头

豆包转写区右下有个圆形 ↓ 按钮。知了现在每来一句就 `scrollTo("bottom")`（`CaptureViews.swift:318`），**读历史的时候会被强行拽到底**。加个「你已离开底部」的判断 + 浮现小圆钮就行，是很便宜的体验修补。

### 3.6 小改：三个胶囊改成菜单

豆包的 自动识别 ⌄ / 不翻译 ⌄ / 保留音频 ⌄ 都带 `⌄`，点开能挑。知了的「自动识别」「保留音频」是开关。留音频改成菜单（存哪、存不存、多长）是有意义的。

## 4. 明确**不要**抄的

| 豆包的做法 | 为什么不要抄 |
|-----------|------------|
| 一切走云端 | 知了识别在本机（`SpeechAnalyzer`），只有翻译和总结走 AI。**这是知了的核心卖点**，「识别在本机完成，只有翻译和总结会用到 AI 服务」这句提示要留着 |
| 右侧只是个思维导图 | 知了的纪要有总结、议题、结论待办、鱼骨图，是**读完能带走**的文档；豆包那种树只是好看 |
| 整段波形 + 拖动定位 | 做 3.3 时只借鉴「看得见全貌」，**拖动定位**先别做：知了的音频要按 `RecordLine.t` 对齐播放引擎，拖动定位牵涉一大片 |
| 大号蓝暂停键 | 豆包是全屏录音器；知了是菜单栏小工具，底部一颗巨型按钮会喧宾夺主。暂停要有，但不用做成 80pt |

## 5. 一个必须先修的回归

合并到 `CaptureViews.swift` 时，**每行的操作按钮整组丢了**：

- 旧 `RecordViews.swift:371` 的 `lineActions` 有四个：▶ 从这里播放 / ✎ 改一下 / 和下一句合并 / 从这里分成两句
- 新 `CaptureViews.swift` 里 `lineActions` **整个函数没了**，`row()` 不再带它
- 结果：`editing` 这个 `@State` 永远不会被设成某句的 id —— **改一句这件事在识别页上已经做不到了**（编辑器代码还留着，但进不去）
- 顺带：播放、合并、拆分也都丢了

另外两处小的：

- `CaptureViews.swift` 的「改一下」若接回去，保存时调的是 `engine.edit(...)` —— 那是**麦克风**的引擎。系统声音那侧的行在 `feed.lines` 里，得按 `source` 分派
- 说话人改名（3.1）在识别页上够不着，只能等会议结束去记录窗口改 —— 实时认人的人希望当场改

---

## 6. 建议的顺序

1. **修回每行操作**（编辑/播放/合并/拆分），按 `source` 分派引擎 —— 这是回归，不是新功能
2. **说话人头像 + 改名下拉** —— 零件全在，接线即可，体验提升最明显
3. **暂停**（`RecordEngine.State` 加 `.paused`，系统声音侧同步）—— 唯一动引擎的一项
4. **滚动到底的浮动按钮** —— 很便宜
5. 整段波形条（要 3 之后）
6. 右侧议题树 —— 最后，且要保证鱼骨图还在
